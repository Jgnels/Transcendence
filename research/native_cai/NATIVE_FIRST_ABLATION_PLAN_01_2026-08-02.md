# Native-First Ablation Plan 01 — Research Design Only

**Date:** 2026-08-02  
**Status:** `DESIGNED_NOT_AUTHORIZED_FOR_APPLICATION`  
**Authority:** `NO_ORDERS` / application `PROHIBITED`

This plan defines future controlled tests. It does not build, install or activate a gameplay-altering pack.

## Goal

Determine whether native WH3 CAI plus narrow DB tuning achieves the project behavior goals well enough that v0.2F/v0.2G never need application authority.

## Conditions

1. **VANILLA_CURRENT** — unchanged current WH3 rows.
2. **SFO_CURRENT** — SFO only; establishes environment/profile effects.
3. **NATIVE_FAIRNESS_ABLATION** — independently authored profile that changes only explicitly player-specific threat/strength multipliers toward symmetric treatment; exact values preregistered before the run.
4. **NATIVE_ACTIVITY_ABLATION** — independently authored minimal task-priority/allocator change targeting one observed failure mode only.
5. **PRIOR_ART_REFERENCE_ABLATION** — one independently reproduced narrow concept inspired by verified prior art; do not stack whole AI mods and do not redistribute third-party rows.

No Transcendence planner issues campaign orders in any condition.

## Observable metrics

Per faction/army trajectory over fixed windows:

- idle-turn rate;
- critical-front coverage rate;
- threatened-settlement response latency;
- directional reversal / intent-churn proxy;
- damaged-army combat re-entry rate;
- healthy-uncommitted-force / reserve proxy;
- territory gain/loss and expansion stalls;
- anti-player targeting index relative to comparable nearby threats;
- army survival and repeated-suicidal-engagement proxy;
- coherent-rival persistence / late-game pressure metrics from v0.2E/F.

## Deletion thresholds

### v0.2F remains evaluator-only if

Across at least five matched seeds per profile and a later late-game cohort, native/current or one narrow native-tuned condition achieves >=90% critical-front coverage and does not regress anti-player fairness or army survival relative to baseline. The exact 90% is a preregistered experiment threshold, not a claim of optimal gameplay.

### v0.2G remains evaluator-only if

Native behavior shows no material double-commitment pathology observable from trajectories, damaged-army misuse stays below 5% of eligible observed offensive engagements, and intent-reversal/churn does not exceed a preregistered threshold often enough to degrade outcomes. The 5% threshold is an experiment trigger, not a known native baseline.

### v0.2I assignment-feasibility bridge is abandoned if

v0.2G remains evaluator-only and no bounded correction requires validating a Transcendence-proposed actor/target assignment. A generic observation bridge may still be built later for measured native behavior.

### Native CAI + bounded tuning becomes the primary application architecture if

A native/tuned condition meets the preregistered challenge/fairness metrics across vanilla and SFO cohorts without requiring project order authority.

## Controller revival threshold

Project-owned planning is not revived merely because a metric is imperfect. It requires a reproducible, material failure that survives at least one narrow native DB intervention and one narrower correction path, plus a controlled shadow demonstration that the project proposal predicts a better outcome.

## Owner burden rule

Do not ask the owner to run WH3 until the exact static profile, save/seed cohort, collection script and pass/fail analysis are prepared offline. Batch read-only observations by authority boundary.
