# Architecture Decision Record — Native CAI Reconciliation

## Decision
Pause the assignment-derived v0.2I live-feasibility path and place v0.2F/v0.2G application-control ambitions behind a native-CAI falsification gate.

## Why
Independent adversarial reviews from Grok, four separately scoped Kimi sessions, and Claude converged after self-correction on the same high-level point: current WH3 already owns materially more strategic machinery than the project had adequately reconciled before building v0.2E-I.

This decision is intentionally asymmetric: native CAI is the default application owner until evidence shows a specific goal cannot be achieved through native behavior, DB tuning, or bounded scripts. Transcendence's evaluator and evidence infrastructure remain active and can falsify that default.

## What this decision does NOT claim
- It does not claim native CAI is optimal.
- It does not claim native CAI has project-style recovery protection, reserves, hysteresis, or multi-faction coordination.
- It does not claim prior-art mods prove gameplay quality.
- It does not authorize DB edits, Lua state mutation, game orders, save writes, or GitHub writes.

## Reversal conditions
A project-owned strategic layer can return to the application path only after a measured native failure is:
1. reproducible;
2. relevant to the player-experience goals;
3. not adequately corrected by a bounded native table/script intervention;
4. better solved by the project layer under controlled ablation;
5. compatible with the project's fairness and authority constraints.
