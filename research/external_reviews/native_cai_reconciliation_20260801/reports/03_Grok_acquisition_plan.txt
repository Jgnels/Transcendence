3. Exact row-diff methodology

Extract vanilla 8.1.x data.pack (or the relevant CAI sub-packs) with the pinned 8.1 schema → export every listed CAI table family as TSV/CSV with full key + value columns.
Extract each mod pack in isolation with the same schema → same TSV export.
For each table:
Compute set difference on primary-key tuples → added / removed rows.
For shared keys: column-wise value diff → changed cells.
Flag any key that appears in multiple mods → load-order collision risk.

Classify every changed row:
Strategic-reasoning (task generators, variables, priorities, personalities, strategic components).
Difficulty / potential / budget / income / upkeep (treat as confounding).
Economy / recruitment quality / unit stats (treat as environment, not pure planning).

Produce a three-column matrix per table: Vanilla value | Mod value | Classification (strategic / confounding / environment).
Any change that increases military budget, faction potential, or aggression multipliers without altering task-generator logic is labelled “potential/budget/bonus effect” and excluded from “intelligence” claims.

5. Patch 8.1 investigation

Exact official wording (totalwar.com / CA community Patch 8.1 notes):
“There are certain Campaign AI tasks that lead to its armies clustering and idling e.g. focusing on defending key regions therefore, we’ve added a new mechanism that allows us to control exactly what the Campaign AI prioritises, depending on how many turns have passed since campaign start. Using this new mechanism we’ve de-prioritised tasks e.g. defending key regions in the late game… Utilising the mechanism above defensive tasks for end game factions have had their priority decreased… The priority of tasks that target enemy forces is increased slightly.”

6. Native-vs-Transcendence ablation dataset (smallest viable)
Minimum set:

3 mid-game saves (turns 40–70) and 3 late-game saves (turns 100+) on Legendary, Karl Franz / Reikland, both vanilla and SFO.
One controlled “high pressure” start and one “low pressure” start.

Capture from WH3 (observer or manual):

All player-visible armies (CQI, strength, stance, region, recovery/replenishment state, movement remaining).
All visible enemy armies and settlements of coherent rivals.
War / peace / alliance matrix for the local theatre.
Turn number, treasury, and basic income.
Which armies are idle / clustered around settlements for ≥3 consecutive turns.
Any army that is damaged (<60 % strength) yet given a non-recovery task.

Computable offline:

Critical-front coverage (does every high-threat border have at least one assigned force).
Recovering-army misuse rate.
Reserve overcommitment (no healthy unassigned army when multiple fronts exist).
Assignment churn (same army re-tasked without material score change within 4 turns).
Coherent-rival persistence (same rival remains the top threat across turns).
Late-game idling/clumping count.
Anti-player bias proxy (fraction of tasks targeting the human vs equal-strength AI).
Expansion effectiveness (settlements gained / armies lost).

7. Stop conditions

NATIVE_CAI_PRIMARY: After row-level diffs + 6 controlled ablations (vanilla / SFO × tuned personalities / budgets / task generators), the evaluator metrics show: critical-front coverage ≥90 %, recovering-army misuse ≤10 %, thrashing rate ≤ project’s own 4-turn baseline, late-game clumping ≤50 % of untuned baseline, and no systematic anti-player bias above the tuned difficulty setting.
HYBRID: Metrics improve under native + DB tuning but residual systematic failures remain on recovery protection or exclusive commitment that cannot be closed by further table edits.
PROJECT_PLANNER_REQUIRED: Tuned native fails the same metrics on ≥2 of the 6 ablation cells and the failure modes match the exact gaps (recovery gate, critical overflow, anti-thrashing hysteresis) that the project layers were designed to address.
