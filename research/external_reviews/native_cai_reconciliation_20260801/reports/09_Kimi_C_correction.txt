3. v0.2E FRONT DETECTION — RECHECK
Proven native: query system, influence map (range + interaction strength), turn-distance, stance-aware distance, task types ("defend settlements when enemy forces present," "defend regions neighboring threat").
Proven v0.2E: visible armies, geometric distance, movement scalar, 2-turn horizon, war state, explicit bounded classifications (SIEGED_COVERED / EXPOSED / CONTESTED / QUIET).
Application: Native influence map detects "extent of every force's range and strength of interaction with assets" — strictly more information than geometric distance. Native distance scaling (4–8 turns, stance-aware) covers the same operational space. Verdict: NATIVE_FIRST.
Evaluator: Native classifications are implicit in generated task types. v0.2E produces explicit, bounded, human-auditable front-state records. Verdict: REFRAME_AS_EVALUATOR_ORACLE.
4. v0.2F PORTFOLIO — RECHECK
Native is proven to have: task generation; multiple generators contributing to tasks; same-type/same-target batching; allocation pairing tasks with armies; distance-sensitive priority; turn-dependent priority modulation (historical/beta).
Native is NOT proven to have: explicit six-slot portfolios; critical overflow; one-aggressive-priority cap; recovery-crisis veto; temporal anti-thrashing; project-style explainability.
v0.2F AS APPLICATION CONTROLLER: REMOVE_FROM_APPLICATION_PATH. Native possesses the underlying strategic capabilities (generation, batching, allocation, distance priority). v0.2F's exact implementation differs, but the functional coverage overlaps. Crucially, no runtime control surface is proven for dynamic portfolio override.
v0.2F AS SHADOW EVALUATOR: KEEP_PROJECT_OWNED. Native does not output explicit bounded portfolios, critical-overflow records, aggressive caps, or recovery vetoes. An independent evaluator providing these benchmarks, explainability, and anti-player-bias auditing retains value regardless of native operational quality.

8. FEASIBLE NATIVE-FIRST ABLATION EXPERIMENT
Question: Does tuned native CAI already achieve the behaviors that v0.2E/F would otherwise control?
Design:
Select 5 Reikland campaign seeds (vanilla + SFO), turns 4–30.
Run 3 static-profile conditions per seed:
Default: unmodified cai_personalities_tables + manager junctions.
Defensive: increased defensive-task weights, reduced aggression weights in DB tables.
Symmetric: reduced anti-player threat multipliers in DB tables (where accessible).
Each turn, extract visible scenario (armies, regions, wars) and run v0.2E + v0.2F shadow.
Observe over 10 turns using only SCRIPT_API_PROVEN / save-visible data:
Front coverage ratio (own army within 2-turn geometric distance of threatened region).
Recovery exposure (low-replenishment armies entering hostile territory).
Rival concentration stability (HHI of enemy strength in wars).
Anti-player targeting index (enemy army movement toward player vs. other targets).
Compare: Does Condition B increase front coverage toward v0.2F's crisis-stabilization posture? Does Condition C reduce anti-player targeting?
Decision rule:
If static DB tuning achieves v0.2F-recommended patterns → native-first is sufficient.
If no static profile achieves the patterns → bounded controller might be justified, but only if a runtime control surface is later proven.
Uses only: controlled saves, observer-visible state, longitudinal position observations, static DB changes, v0.2E/F shadow outputs, no Transcendence game orders.
